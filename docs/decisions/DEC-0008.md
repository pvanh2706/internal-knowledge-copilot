# DEC-0008 — S01 Platform Identity, Local Authentication and Bootstrap Design

**Category:** Identity & Authorization Architecture (S01 detail of DEC-0005)  
**Decision status:** **APPROVED**  
**Decision authority:** Product Owner  
**Approved on:** 2026-10-30  
**Documentation publication:** This documentation-only PR; merge pending explicit PO approval  
**Implementation authorization:** **NOT AUTHORIZED**

## 1. Context

[DEC-0005](DEC-0005.md) established separation between platform and tenant administrative authority and deferred identity model, authentication, bootstrap, schema and migration detail to S01. The existing `users` have mandatory `TenantId` and `UserRole.Admin`; platform tenant management currently uses that tenant-local Admin role. S01 resolves the design-level choices without promoting existing tenant users.

## 2. Approved subdecisions (as PO selected)

| ID | Options considered | Selection | Decision |
|---|---|---|---|
| **S01-Q01** | A: platform privilege on tenant `UserEntity`; B: separate platform identity | **B** | Platform identity/account distinct from tenant users |
| **S01-Q02** | A: local platform credentials; B: OIDC/SSO first | **A** | Dedicated local Platform Admin authentication, with future OIDC/SSO extensibility |
| **S01-Q03** | A: restricted operator CLI; B: deployment-config startup bootstrap | **A** | First Platform Admin created through restricted CLI, not public API or automatic default seed |
| **S01-Q04** | A: separate `platform_security_state`; B: infer from admin-account history | **A** | Dedicated one-time bootstrap state table independent of account count |

## 3. Architecture and trade-offs

- Separate platform identity provides a clear trust boundary and avoids introducing privilege escalation via tenant `UserRole`, at cost of schema/auth/API/audit and UI work.
- Local authentication reduces initial dependency on an enterprise identity provider but requires secure password hashing, lockout, restricted privileged session, revocation, recovery and MFA before internet-exposed production.
- CLI bootstrap avoids a public first-admin endpoint but needs authorized operator access and a recovery procedure.
- Dedicated state table avoids re-opening bootstrap when the last admin is disabled/deleted, **but a database restore can revert this table**. A separately protected provisioning/recovery proof and deny-by-default reconciliation are required; no claim of absolute rollback immunity.

The exact table columns, key-rotation policy, CLI UX and recovery technology are governed by [the approved S01 baseline](../architecture/S01_TECHNICAL_DESIGN_BASELINE_V1.0.md) and later implementation/security evidence; no code/migration is approved by these choices alone.
